# План реализации

Цель: новая версия mdpravo.ru — молодёжный, понятный и аккуратный сайт юридической компании и рабочий личный кабинет с делами, документами и оплатой. Исходное ТЗ: `docs/brief/` (читаемая версия) и `docs/brief/ORIGINAL_BRIEF.md`.

## Архитектура

```
Браузер ──HTTPS──> nginx (TLS, gzip, лимит размера тела, статика /downloads)
                     │
                     ▼
              Node.js ≥ 22.13  (src/server.js, один процесс)
              ├─ роутер + серверный рендер HTML (src/lib, src/views)
              ├─ сессии в БД, CSRF, CSP, rate limit (src/lib/security.js)
              ├─ SQLite (node:sqlite, WAL)  ── data/app.sqlite
              ├─ приватные файлы клиентов   ── storage/  (вне webroot)
              ├─ почта: SMTP (src/lib/mailer.js)
              └─ оплата: адаптер ЮKassa / тестовый (src/payments)
```

Решения и причины:

| Решение | Почему |
|---|---|
| Серверный рендер без фреймворка | Нет доступа к npm; быстрые страницы без тяжёлого JS (цель Lighthouse Performance ≥ 90) |
| Шаблонизатор с автоэкранированием (`html```) | Защита от XSS по умолчанию |
| SQLite + слой репозиториев | Один файл, простые бэкапы; репозитории позволяют перейти на PostgreSQL |
| Сессия в БД, cookie `HttpOnly; Secure; SameSite=Lax`, хеш идентификатора в БД | Утечка БД не даёт угнать сессии |
| scrypt (N=2^15) для паролей | Встроен в Node, устойчив к перебору на GPU |
| Подтверждение оплаты только сервером | Статус берётся из API провайдера, а не из редиректа или тела webhook |
| Файлы клиентов вне публичной папки, выдача после проверки прав | Нет постоянных публичных ссылок на конфиденциальные документы |

## Роли

- **client** — видит только свои обращения, дела, документы, счета.
- **lawyer** — видит назначенные дела, меняет статусы, загружает документы, выставляет счета.
- **admin** — всё, что lawyer, плюс управление пользователями и всеми делами.

Права проверяются на сервере в каждом обработчике через `requireCaseAccess()`; скрытие кнопок во frontend не считается защитой.

## Статусы дела

| Код в БД | Подпись для клиента |
|---|---|
| `new` | Новое обращение |
| `review` | На рассмотрении |
| `need_docs` | Ожидаем документы |
| `need_payment` | Ожидаем оплату |
| `in_progress` | В работе |
| `done` | Завершено |
| `closed` | Закрыто без работы |

## Этапы и критерии готовности

| Этап | Результат | Готово, когда |
|---|---|---|
| A. Аудит | `docs/PROJECT_AUDIT.md` | факты отделены от выводов, блокеры названы |
| B. Резервирование | отдельный репозиторий, ветка `main`, ничего в старом проекте не трогаем | старый сайт продолжает работать до переключения DNS |
| C. Дизайн-система | логотип, токены, шрифты, компоненты | `public/brand`, `public/css`, тест контраста зелёный |
| D. Публичная часть | все 239 URL, главная, услуги, база знаний, поиск, контакты | тест `urls.test.js` зелёный, ручная проверка на 320–1920 px |
| E. Кабинет | вход, обращения, дела, сообщения, закладки, профиль | интеграционные тесты входа и изоляции клиентов зелёные |
| F. Документы и оплата | загрузка/скачивание с проверкой прав, счета, ЮKassa, webhook | тесты: чужой документ → 404, повторный webhook не дублирует, сумму нельзя подменить |
| G. Адаптивность | проверка ключевых страниц на 9 ширинах | `tests/e2e/responsive.py` без горизонтальной прокрутки |
| H. Тесты | `npm test` | все тесты проходят, отчёт в `docs/TEST_REPORT.md` |
| I. Запуск | `DEPLOYMENT.md`, `ROLLBACK.md`, `.env.example` | инструкция проверена на чистой установке в контейнере |

## Что не входит в эту итерацию

- Импорт аккаунтов, обращений и платежей старого кабинета — ждёт дампа БД (блокер 1 в аудите).
- SMS-коды и вход через Яндекс ID — ждут провайдера и OAuth-приложения.
- Юридические калькуляторы с ключевой ставкой ЦБ — нужна проверяемая таблица ставок; страница `/knowledge/calculators/` сохранена с калькулятором договорной неустойки (не зависит от внешних ставок).
